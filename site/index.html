Three ways to run it

One Rust core, compiled three ways — native for the desktop, WebAssembly for the browser. Same rendering, same editing, same documents-never-leave-your-machine. Pick whichever suits you; nothing is held back in any of them.

Questions

The ones that actually get asked about an editor that doesn't upload anything.

Is OpenPdfEdit free?

Yes, apart from two tools. Annotating, editing text, redacting, filling and signing forms, reorganising pages, merging, splitting and comparing are all free, with no page limit, no export cap and nothing of ours stamped on the output. Two Supporter tools — watermarking and OCR — cost 1,000 credits once, for both together.

Are my documents uploaded anywhere?

No. The desktop app has no HTTP client in the binary at all — not disabled, not opt-out, absent — and the web app does the work in the page rather than on a server, so there is nowhere for a document to go. The source is public and the claim is checkable.

Do I need an account?

Not to install it, use it, or save a file. An account exists only for the two Supporter tools, and only to carry the one-time payment for them.

Does it work offline?

Yes. The desktop app never needs a network. The web app needs one only to load the page the first time; after that it keeps working with the network off, including after a reload.

Can it edit the text already in a PDF?

Yes. You can replace a line in place, move a run of text, and reposition an image. A PDF stores glyphs rather than paragraphs, so an edited line does not reflow the ones around it, and when the original font isn't embedded the substitute is named rather than swapped in quietly.

Is the redaction real, or a black box over the text?

Real. The text is removed from the page's content stream, including text inside form XObjects, and the covered pixels of an image are overwritten rather than the image being hidden. The file is then rewritten rather than appended to, so the removed content is not recoverable from an earlier revision. The box drawn on top is a second line of defence, not the mechanism.

Can it read a scanned document?

Yes — OCR adds a searchable, selectable text layer under the scan without changing a pixel of how the page looks. Twelve languages ship with it, including Simplified and Traditional Chinese, Japanese, Korean, Arabic and Russian. Recognition runs on your machine like everything else. It is one of the two Supporter tools.

What does it run on?

A native app for macOS (Apple Silicon) and Windows; a web app in Chrome, Edge, Firefox and Safari; and a Chrome extension. On a phone the web app lays itself out for the screen and can be added to the home screen. Saving over the original file, rather than downloading a copy, needs Chrome or Edge.

How is it different from the online PDF tools?

Those upload your file to a server, do the work there, and send it back — which is why they can meter it by page and by day. This does the work where the file already is, so there is no queue, no size limit, no daily cap, and no copy of your document on someone else's disk.

Is it open source?

Yes, under MIT or Apache-2.0, on GitHub. The same build everyone else gets — you can read it, build it yourself, or fork it.
